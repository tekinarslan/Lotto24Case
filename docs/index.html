Introduction

In Germany there are two major draw-based lotteries:

  • Lotto 6aus49: In this lottery, players select six numbers from a pool of 49 and an additional "Super Number" between 0 and 9. There is a draw where drawn numbers are compared to picked numbers. The prize depends on how many numbers match the drawn winning numbers.
  • Eurojackpot: Players choose five numbers from a pool of 50 and two "Euro Numbers" from a separate pool of 12. To win the jackpot, all seven numbers must be correct.
  • Supplementary lotteries: These are optional lottery games, such as Spiel 77 or Super 6, which can be played alongside the main lottery and offer additional chances to win.

Each lottery draw has

  • A last draw date with draw results (which numbers were drawn on this draw date)
  • Next draw date in the future (in which players can participate)
  • Maybe a jackpot height (directly after a draw it is not there, because it is not known if a player has picked the right numbers, yet)

User Story

As a user I want

  • To install an app on my Android device which is small and just displays the results of my favorite lotteries
  • The last draw results for LOTTO 6aus49 and Eurojackpot
  • The jackpot heights (if there are any)
  • and the next draw date(s) to be visible in a "draw results" screen or (bonus) a draw result widget

so, I can decide if I want to participate in the next draw.

Features to be implemented.

Must have:

  • Actual numbers are displayed in a ball
  • Next draw date is displayed
  • The jackpot heights are displayed (if applicable)
  • Jetpack Compose should be used as a framework

Bonus:

  • There is also a widget
  • If you click anywhere, it will open a link to our website or to our native app’s Play Store page
  • Spiel77 and SUPER6 are also displayed.

Tech Stack & Architecture

Modular boundaries, library selections, architectural patterns, and trade-off rationales.

1. Modular Project Architecture

AGP 8.5+ & Modern KMP Modular Structure

The project follows the official decoupled structure recommended for modern Compose Multiplatform apps:

Module Type Responsibilities
:androidApp com.android.application Android application entry point (MainActivity), Android Manifest, application launcher icons, and Jetpack Glance AppWidget.
:shared com.android.kotlin.multiplatform.library Houses 100% of multiplatform business logic, Ktor HTTP client, domain models, Koin DI graph, and CMP Compose UI screens & design components in commonMain.
:iosApp Xcode Project Native iOS wrapper rendering the shared Compose UI via UIViewController bridge.

2. Package-by-Layer Architecture (Inside :shared)

shared/src/commonMain/kotlin/de/lotto24case/
├── domain/                    <-- Zero external framework dependencies (Pure Kotlin)
│   ├── model/                 <-- Sealed LotteryDraw, Jackpot, BallItem, GameRules
│   ├── repository/            <-- LotteryRepository interface
│   └── usecase/               <-- GetLotteryResultsUseCase, FormatJackpotUseCase
│
├── data/                      <-- Implements domain contracts
│   ├── remote/                <-- Ktor HTTP client, ApiService, DTOs
│   ├── local/                 <-- CacheDataSource (Offline fallback)
│   ├── mapper/                <-- DTO -> Domain mappers
│   └── repository/            <-- LotteryRepositoryImpl
│
├── presentation/              <-- UI Layer (Compose Multiplatform)
│   ├── components/            <-- LotteryBall, NextDrawPill, LotteryCard
│   ├── screen/                <-- DrawResultsScreen, DrawResultsUiState
│   ├── viewmodel/             <-- DrawResultsViewModel (MVI / UDF)
│   └── theme/                 <-- Typography, Colors, Dimens, Shape
│
├── di/                        <-- Koin modules (NetworkModule, DataModule, DomainModule, UiModule)
└── navigation/                <-- ExternalNavigator abstraction (Web & PlayStore intents)

3. Technology Choices & Architectural Trade-offs

Technology Role Why Chosen & Trade-off Consideration
Koin 4.2.2 Dependency Injection Native KMP support, official Compose Multiplatform viewmodel injection (koinViewModel()), zero reflection or KSP build-overhead. Hilt was ruled out as it cannot target multiplatform iOS.
Ktor 3.6.1 HTTP Client Modern coroutines-native KMP networking with ContentNegotiation and MockEngine for unit testing without live servers.
kotlinx.serialization 1.8.0 JSON Serialization Fast compile-time generated serializers. Tolerates missing fields and heterogeneous structures cleanly.
kotlinx-datetime 0.8.0 Timezone & Dates Strict ISO-8601 parsing and accurate timezone conversions between Berlin and Helsinki draw locations.
kotlinx.collections.immutable 0.5.2 Compose Recomposition Ensures lists of numbers, balls, and cards are marked @Immutable by the Compose compiler, preventing skippable recomposition penalties.
Jetpack Glance 1.2.0 Android App Widget Modern declarative Compose syntax for Android AppWidgets, residing cleanly in :androidApp.
ComposablePreviewScanner 0.10.0 Screenshot Testing Automated test scanning of all @Preview composables to guarantee visual regression safety.

2. Physics-Based Animations (Spring Dynamics)

Spring Physics Parameters

Instead of generic linear or tween animations, Compose spring() physics will be used:

  • Ball Drop & Entrance: Staggered entrance using Spring.DampingRatioMediumBouncy (0.75f) and Spring.StiffnessLow (200f) to mimic real lottery balls bouncing into position.
  • Card Press Feedback: graphicsLayer { scaleX = animatedScale; scaleY = animatedScale } using Spring.DampingRatioHighBouncy for tactile button clicks.
  • Jackpot MIO Pulse: Subtle breathing/pulsing animation highlighting high jackpot stakes (> 10 MIO €).
